### Why the module path is not decorative

A Go module path is the URL the toolchain fetches from, not a label. `go install
github.com/hagnerk/mqtt2bdd/...` and `go get` both resolve the path over HTTPS and expect the
repository serving it to declare that same path in its own `go.mod`; a mismatch is a hard error, not
a warning. Relying on GitHub's account-rename redirect (`spydemon` → `hagnerk`) is not a safe
substitute: a freed username can be re-registered by anyone, at which point the old path resolves to
a stranger's repository. [Source: docs/prd.md:684-689]

This story is cheap precisely because it is early: the module has never been published, has no tag
and no git remote (`git remote -v` → empty, confirmed for this draft), so there is no downstream
consumer, no need for a `retract` directive, and no `/v2` major-version path semantics to handle.
Story 4.2 pushes to GitHub and closes that window permanently — which is why the epic sequences this
