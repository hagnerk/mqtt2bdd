## Story

**As a** developer,
**I want** to establish a connection to the PostgreSQL database with connection pooling,
**so that** I can persist MQTT messages efficiently.

## Acceptance Criteria

1. `internal/database/client.go` defines `Client` struct wrapping a pgx connection pool
2. `go.mod` includes dependency: `github.com/jackc/pgx/v5` (provides both `pgx/v5` and `pgx/v5/pgxpool` sub-packages from a single module entry)
3. `NewClient(cfg *config.Config, l *slog.Logger)` returns `*Client` with DSN constructed from config using libpq key=value format: `"host=... port=... dbname=... user=... password=..."`
4. `Connect(ctx context.Context) error` establishes the connection pool and verifies connectivity with a ping
5. Connection pool configuration: `MinConns = 1`, `MaxConns = 5`, `MaxConnIdleTime = 5 * time.Minute`
6. `Connect()` logs connection attempt (INFO) with host and database name, and success (INFO) or failure (ERROR) with the same fields
8. `Close()` method cleanly closes the connection pool and logs disconnection (INFO)
9. `main.go` updated to create database client, connect on startup, and defer close on exit (after MQTT setup)
10. Manual test: Run application, verify logs show successful PostgreSQL connection to `mqtt2bdd-dev-postgres` container
11. Application exits gracefully if database connection fails with clear error message including connection details
12. All code passes `go fmt`, `go vet`, and `staticcheck`

### Database Client — Architecture Specification

**Component specification from architecture:**

```go
// Key Interfaces
func NewClient(cfg *config.Config, logger *slog.Logger) *Client
func (c *Client) Connect(ctx context.Context) error
func (c *Client) Close()
```

**Struct fields:**
- `pool *pgxpool.Pool` — the connection pool; nil until `Connect` succeeds
- `dsn string` — full connection string including credentials; NEVER logged (same principle as MQTT not logging credentials — SEC-001)
- `host string` — PostgreSQL host retained for log context
- `dbName string` — database name retained for log context
- `logger *slog.Logger` — structured logger

**Note:** `NewClient` stores the DSN (including credentials) in the struct. This does not increase security exposure since the credentials are already in memory via the `config.Config` passed to `NewClient`. Following the MQTT pattern of pre-computing the connection string at construction time, not at `Connect` time.

[Source: docs/architecture/components.md#component-database-client]

### Connection Pool Configuration

From architecture specification:

```go
const (
    minConns        = int32(1)    // maintain at least one connection
    maxConns        = int32(5)    // sufficient for single DB writer goroutine
    maxConnIdleTime = 5 * time.Minute
)
```

Applied via `pgxpool.ParseConfig` → modify → `pgxpool.NewWithConfig`:

```go
poolConfig, err := pgxpool.ParseConfig(c.dsn)
if err != nil {
    // ... error handling
}
poolConfig.MinConns = minConns
poolConfig.MaxConns = maxConns
poolConfig.MaxConnIdleTime = maxConnIdleTime

pool, err := pgxpool.NewWithConfig(ctx, poolConfig)
```

**Why Ping after NewWithConfig?**
`pgxpool.NewWithConfig` with `MinConns = 1` will attempt to create one connection at startup. However, adding an explicit `pool.Ping(ctx)` makes the connectivity verification intent clear and provides a distinct error path — consistent with the educational objective of explicit, readable code.

[Source: docs/architecture/components.md#component-database-client]

### DSN Construction

Le format libpq key=value est utilisé à la place du format URL, ce qui évite tout problème d'encodage de caractères spéciaux dans les mots de passe (`@`, `/`, `?`, `#`, etc.) :

```go
dsn := fmt.Sprintf("host=%s port=%d dbname=%s user=%s password=%s",
    cfg.PostgresHost,
    cfg.PostgresPort,
    cfg.PostgresDB,
    cfg.PostgresUser,
    cfg.PostgresPassword,
)
```

Les valeurs dans le format key=value sont traitées comme des chaînes littérales par pgx — aucun encodage URL n'est nécessaire. Ce format est supporté nativement par pgx v5 et par la libpq sous-jacente. La valeur du champ `password` est délimitée par les espaces ; si elle contient des espaces, pgx gère correctement la lecture via son parser interne.

### Connect Method — Full Implementation

```go
// Connect establishes the pgx connection pool configured with MinConns=1 and
// MaxConns=5, then verifies connectivity with a Ping. It logs the attempt and
// outcome. Returns an error if the pool cannot be created or the initial ping
// fails, having already logged the failure with host and database context.
func (c *Client) Connect(ctx context.Context) error {
    c.logger.Info("connecting to PostgreSQL", "host", c.host, "database", c.dbName)

    poolConfig, err := pgxpool.ParseConfig(c.dsn)
    if err != nil {
        c.logger.Error("PostgreSQL connection failed", "host", c.host, "database", c.dbName, "error", err)
        return fmt.Errorf("failed to parse PostgreSQL DSN for %s/%s: %w", c.host, c.dbName, err)
    }

    poolConfig.MinConns = minConns
    poolConfig.MaxConns = maxConns
    poolConfig.MaxConnIdleTime = maxConnIdleTime

    pool, err := pgxpool.NewWithConfig(ctx, poolConfig)
    if err != nil {
        c.logger.Error("PostgreSQL connection failed", "host", c.host, "database", c.dbName, "error", err)
        return fmt.Errorf("failed to create PostgreSQL connection pool for %s/%s: %w", c.host, c.dbName, err)
    }

    if err := pool.Ping(ctx); err != nil {
        pool.Close()
        c.logger.Error("PostgreSQL connection failed", "host", c.host, "database", c.dbName, "error", err)
        return fmt.Errorf("failed to ping PostgreSQL at %s/%s: %w", c.host, c.dbName, err)
    }

    c.pool = pool
    c.logger.Info("PostgreSQL connected", "host", c.host, "database", c.dbName)
    return nil
}
```

Stop with Ctrl+C — expected output (note: Ctrl+C sends SIGINT, which unblocks `select{}` and triggers defers):

> **Important:** `select {}` blocks forever unless the process receives a signal. Ctrl+C sends SIGINT, which terminates the process. In Go, when a goroutine executing `main()` terminates via signal, deferred calls in `main()` DO run before exit (unlike SIGKILL). So `defer dbClient.Close()` and `defer mqttClient.Disconnect()` will both execute on Ctrl+C.

```

```
