### The `EffectiveLevel`/`isKnownLevel` Nit — Why Not an AC

The orchestrating brief for this draft asked for an explicit ruling, not a default, on whether this item
becomes an AC. **Ruling: Dev Notes observation, not an AC.**

Gate 2.6's `maintainability` note is the direct evidence: *"One nit, story-sanctioned and not raised as a
finding: `EffectiveLevel` and `isKnownLevel` each enumerate DEBUG/INFO/ERROR. The story explicitly permitted
this shape provided the level mapping exists once, which it does — but the accepted set is now written
twice... A shared map would remove the seam entirely."* This is qualitatively different from FIND-021, which
gate 2.6 listed as a numbered `top_issues` entry with a `suggested_owner` and a concrete extraction — the
`EffectiveLevel` nit appears only in the prose of `nfr_validation.maintainability` and in the `recommendations
.future` list, phrased as "Consider collapsing... not prescribing a change."

Two further reasons, specific to this story's own charter:

1. **It is not a testability gap.** FIND-021 exists because the `-1` sentinel branch is genuinely
   *unreachable* by a test today (no seam, only reachable via a real ticker). `EffectiveLevel` and
   `isKnownLevel` are each **already** independently covered — `TestEffectiveLevel` (six table-driven cases)
   exercises `EffectiveLevel` directly, and `isKnownLevel` is exercised indirectly through every
   `TestNewLogger` case (its return value drives the `unknown` bool). Collapsing the two switch statements
   onto one `map[string]slog.Level` would change *implementation*, not *coverage* — this story's own AC1
   ("comprehensive unit tests... for `logger`") is already satisfied for this exact function pair, both
   before and after such a collapse.
2. **Promoting it would import unrelated refactor scope into a testing story.** This story's charter (per
   its own title and AC1–11) is "write tests," not "refactor `internal/logger`." Making the collapse an AC
   would mean touching production code for a reason that produces zero new test coverage — the same
   scope-creep guard Story 3.3 applied when it declined to let AC12's "permanent resubscribe failure"
   question (a real, PO-flagged design gap) become a new AC or Dev Note prose, routing it instead to a
   freshly-tracked QA finding (REL-001) at that story's own gate.

The Dev agent may fold the collapse into `internal/logger/logger.go` opportunistically while working Task 2
(e.g., if `TestNewLogger_UnknownLevelWarning` makes the duplication newly visible) — this is explicitly
**latitude, not a requirement**. If done, it must not change either function's observable behaviour: the
accepted level set (`DEBUG`, `INFO`, `ERROR`, case-insensitive) and the INFO-default for everything else
stay exactly as they are.

```go
func healthCheckLoop(l *slog.Logger, mqttClient *mqtt.Client, dbClient *database.Client, msgChan <-chan mqtt.Message, done <-chan struct{}) {
	ticker := time.NewTicker(defaultHealthCheckInterval)
	defer ticker.Stop()

	var lastWriteCount uint64

	for {
		select {
		case <-ticker.C:
			used := len(msgChan)
			capacity := cap(msgChan)
			utilization := bufferUtilizationPercent(used, capacity)

			// indistinguishable from a parsing gap, where the sentinel is greppable.

				lastWriteAgeSeconds = int64(time.Since(lastWriteAt).Seconds())
			}

			// ... buffer_high WARN branch, unchanged ...
		case <-done:
			return
		}
	}
}
```

The `-1`-sentinel block (five lines) is inline inside the ticker branch, reading `dbClient.LastWriteAt()`
directly and calling `time.Since(...)` — both of which require either a real `*database.Client` or a real
clock tick to reach, which is exactly why gate 2.6 called it "proven only by manual replay."

### AC12 — The Fix

Extract the same shape as the existing `connectionStatus`/`bufferUtilizationPercent` pair (both already pure,
already unit-tested in `main_test.go`):

```go
// writeAgeSeconds returns the number of whole seconds between lastWrite and now, or -1
// if lastWrite is the zero time.Time (no successful write has happened yet). -1 rather
// than an omitted field: an absent value would be indistinguishable from a parsing gap,
// where the sentinel is greppable.
func writeAgeSeconds(lastWrite, now time.Time) int64 {
	if lastWrite.IsZero() {
		return -1
	}
	return int64(now.Sub(lastWrite).Seconds())
}
```

`healthCheckLoop`'s ticker branch becomes:

```go
lastWriteAgeSeconds := writeAgeSeconds(dbClient.LastWriteAt(), time.Now())
```

No other line in `healthCheckLoop` changes. `time.Now()` is passed in explicitly (not called inside the
helper) so the helper stays pure and the "no design cost, no injectable interval" property gate 2.6 asked
for is preserved exactly — the helper takes two `time.Time` values and returns an `int64`, nothing else.

### AC12 — Unit Test (`cmd/mqtt2bdd/main_test.go`)

Same table-driven shape as the file's existing two tests:

```go
func TestWriteAgeSeconds(t *testing.T) {
	now := time.Date(2026, 7, 26, 12, 0, 0, 0, time.UTC)
	tests := []struct {
		name      string
		lastWrite time.Time
		want      int64
	}{
		{"never written yet (zero time)", time.Time{}, -1},
		{"written 48 seconds ago", now.Add(-48 * time.Second), 48},
		{"written this instant", now, 0},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			t.Parallel() // pure function, no shared state
			if got := writeAgeSeconds(tt.lastWrite, now); got != tt.want {
				t.Errorf("writeAgeSeconds(%v, %v) = %d, want %d", tt.lastWrite, now, got, tt.want)
			}
		})
	}
}
```

A fixed `now` (not `time.Now()`) keeps the test deterministic — this is exactly the property the extraction
was for: the sentinel branch is now reachable with two `time.Time` literals and no ticker, no goroutine, no
real `*database.Client`.

### `t.Parallel()` Guidance, Per Package

AC8 asks for `t.Parallel()` "where appropriate," and Story 3.3's Dev Notes carved out an explicit exception
for `cmd/mqtt2bdd`'s **integration** tests (the shared hardcoded MQTT client ID collision) — that exception
is scoped to that one integration package and does not apply here. This story's package-level unit tests in
`internal/` have no such collision risk and should default to `t.Parallel()` unless a specific, stated reason
says otherwise:

- **`internal/config`**: **no** `t.Parallel()`. `t.Setenv` (used throughout `config_test.go`) explicitly
  panics if called from a parallel subtest or a subtest with a parallel ancestor — this is a Go stdlib
  restriction, not a project preference. Correctly absent today; do not add it.
- **`internal/logger`**: **yes**, on every subtest. No shared state (`bytes.Buffer` is constructed fresh per
  subtest); safe to add throughout.
- **`internal/mqtt`**: **mixed, by test.** The two pre-existing reconnect tests mutate the shared
  package-level `defaultMQTTReconnectInterval` var and must stay sequential (no `t.Parallel()`). All new
  tests in Task 3 construct an independent `*Client` and touch no shared state — add `t.Parallel()` to each.
- **`internal/database`**: **yes**, on the four new `Connect`-failure tests and on
  `TestClientHealthZeroValues`'s existing three subtests (retrofitted — they predate this story and have no
  parallel-safety concern).
