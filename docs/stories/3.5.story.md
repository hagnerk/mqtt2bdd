### Features Content

Grounded in `cmd/mqtt2bdd/main.go` and `internal/*` — every bullet below traces to real, shipped code:

- Wildcard MQTT subscription (`#`) — device-agnostic, no per-sensor configuration needed. [Source: internal/mqtt/client.go; docs/architecture/security.md#input-validation]
- Automatic MQTT reconnection with resubscribe retry, verified by `internal/mqtt/client_test.go`'s
  `TestReconnectLoop_RetriesResubscribeUntilSuccess`/`_ResubscribeStopsOnShutdown` (added at Story 3.3 for
  FIND-010). [Source: internal/mqtt/client.go]
- In-memory buffered channel decoupling MQTT reception from database writes, with backpressure: the producer
  blocks once the buffer (`BUFFER_SIZE`, default 1000) is full, rather than dropping messages silently.
  [Source: cmd/mqtt2bdd/main.go:261-275]
- Automatic insert retry on database outage — a message is retried every 10 seconds
  (`defaultRetryIntervalOnDatabaseFailure`) until it succeeds; no message is lost during an outage.
  [Source: cmd/mqtt2bdd/main.go:20-21,48-70]
- Idempotent writes via `INSERT ... ON CONFLICT (sensor, date) DO NOTHING`. [Source: docs/architecture/database-schema.md#application-insert-operations]
- Graceful shutdown on SIGTERM/SIGINT: stops the MQTT client, drains all buffered messages (bounded by a
  30-second timeout), then closes the database pool in order. [Source: cmd/mqtt2bdd/main.go:283-317]
- Periodic health-check log line (every 60 seconds): MQTT/DB connection status, buffer utilization, and time
  since the last successful write, plus a separate WARN when buffer utilization exceeds 80%.
  [Source: cmd/mqtt2bdd/main.go:132-180]
- Structured, human-readable logging (`log/slog` text handler) with per-component tagging (`main`, `mqtt`,
  `database`) and UTC timestamps. [Source: internal/logger/logger.go]
- Statically-linked, minimal production Docker image (~18.5 MB, measured), running as a non-root user.

### Architecture Content

ASCII diagram tracing the real shape in `cmd/mqtt2bdd/main.go` (three goroutines plus the Paho-managed
callback), for use in a fenced code block:

```
                    ┌─────────────────────┐
                    │     MQTT Broker      │
                    │     (Mosquitto)      │
                    └──────────┬───────────┘
                               │ publishes to any topic
                               ▼
                    ┌─────────────────────┐
                    │   MQTT Client        │  Paho callback goroutine
                    │  (internal/mqtt)      │  wildcard subscription "#"
                    └──────────┬───────────┘
                               │ send (blocks if buffer is full)
                               ▼
                    ┌─────────────────────┐
                    │  Buffered Channel     │  chan mqtt.Message
                    │  cap = BUFFER_SIZE    │  default 1000
                    └──────────┬───────────┘
                               │ receive
                               ▼
                    ┌─────────────────────┐
                    │  DB Writer Goroutine  │  dbWriterLoop()
                    │  (cmd/mqtt2bdd)       │  retries every 10s on failure
                    └──────────┬───────────┘
                               │ INSERT ... ON CONFLICT DO NOTHING
                               ▼
                    ┌─────────────────────┐
                    │      PostgreSQL       │
                    │   sensor_metrics      │
                    └─────────────────────┘

  Main goroutine: initializes config/logger/mqtt/database, starts the two
  goroutines above plus a third (Health Check, below), then blocks on
  SIGTERM/SIGINT and coordinates the drain-then-exit shutdown sequence.

  Health Check goroutine: every 60s, reads channel length/capacity and both
  clients' connection status (no writes, no sends) and logs one status line;
  logs a separate WARN if the buffer is above 80% utilization.
```

Narrative must mention: (1) the wildcard subscription is device-agnostic — no config per sensor; (2) the
channel is the sole coupling point between MQTT reception and database writes — this is Go's CSP
("communicate by sharing channels") pattern, worth calling out explicitly as a learning point per this
story's own charter; (3) backpressure is intentional, not a bug — a full buffer means the producer blocks
rather than the process growing memory unboundedly; (4) the health-check goroutine observes but never
mutates the channel or either client. [Source: cmd/mqtt2bdd/main.go:78-180,240-259; docs/architecture/components.md#concurrency-architecture]

### Troubleshooting Content

Concrete, code-grounded scenarios only:

- **MQTT connection failures.** `MQTT_BROKER`/`MQTT_PORT` must match the broker's hostname as seen *inside*
  the Docker network, not the host-published port — a common mistake is using the dev stack's container
  name (`mqtt2bdd-dev-mosquitto`) while pointed at the prod stack, or vice versa.
- **PostgreSQL authentication failures.** `POSTGRES_PASSWORD` only takes effect on the container's *first*
  boot against an empty data directory — the `init-db` scripts do not re-run on a later password change.
  Changing `.env`/`.env.prod` after the volume already has data will not update the database user's actual
  password; recreate the volume or change the password inside PostgreSQL directly.
- **Forgetting `--env-file .env.prod`.** Every command against `docker-compose.prod.yml` needs it —
  `ps`, `logs`, `exec` included, not just `up` — because the values arrive via Compose variable
  interpolation, which only `--env-file` feeds.
- **`buffer_full` WARN log line.** Means the database is not keeping up with the MQTT broker; the
  application blocks the producer rather than dropping messages, so the operator's window to react is the
  remaining buffer headroom (`BUFFER_SIZE`, default 1000 messages, roughly ten minutes of downtime at 100
  messages/minute).
- **Health check reports `unhealthy` but the container is not restarted.** This is by design, stated in
  `docker-compose.prod.yml`'s own comment: `restart:` reacts to container *exit*, not to `unhealthy` status;
  watch `docker compose ps` or point an external watchdog at it.
- **Permission errors on the mounted project directory** (`dev/docker-compose.yml`'s `../:/app` bind mount)
  — typically a Docker Desktop file-sharing setting on macOS/Windows; ensure the repository's parent
  directory is within Docker's allowed file-sharing paths.
