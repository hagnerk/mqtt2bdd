### Deferred: The Publication Runbook (ACs 6, 7, 8, 10)

**Why these are deferred rather than done.** Creating a public repository and pushing history to it
is outward-facing and irreversible: once fetched, a clone cannot be recalled, and a published module
path cannot be changed retroactively for anyone who has already resolved it. That decision belongs to
the maintainer, who has deferred it. This is a *deferral*, not a blocker for the rest of the epic:
Story 4.3 writes the release workflow as a file in `.github/workflows/`, which is authored and
reviewable locally; only its AC12 end-to-end rehearsal shares this dependency.

**The `gh` CLI is present and authenticated** on this machine (`/opt/homebrew/bin/gh`, logged in to
`github.com` as `hagnerk`, git protocol `ssh`). Not executing the runbook is a choice, not an
incapacity. Record it as such.

**Preconditions — all satisfied by this story, verify before running anything below:**

| Precondition | Check | Why it matters |
| --- | --- | --- |
| Module path matches the target repository | `head -1 go.mod` → `module github.com/hagnerk/mqtt2bdd` | AC6. A divergence and `go install github.com/hagnerk/mqtt2bdd/...` cannot resolve. |
| History audited clean | Task 4, all four commands | AC4. A secret published is a secret retrievable forever. |
| Nothing published by accident | `git remote -v` → empty | Confirms this is genuinely the first publication. |
| Working tree clean | `git status --short` → empty | AC5. |
| On `main` | `git rev-parse --abbrev-ref HEAD` → `main` | AC7 pushes `main` specifically. |

**Runbook:**

```bash
# AC6 + AC8 — create the public repository with its description and topics in one call.
gh repo create hagnerk/mqtt2bdd --public \
  --description "Bridge home automation MQTT messages into PostgreSQL. A single wildcard subscription, a buffered channel, and a static Go binary." \
  --source . --remote origin --push

# AC8 — topics are not settable by `gh repo create`; they need a second call.
gh repo edit hagnerk/mqtt2bdd \
  --add-topic go --add-topic mqtt --add-topic postgresql \
  --add-topic home-automation --add-topic iot --add-topic docker

# AC7 — verify the remote and that main is fully pushed.
git remote -v
git rev-parse HEAD && git rev-parse origin/main   # must match

# AC10 — verify rendering by eye at https://github.com/hagnerk/mqtt2bdd :
#   - the Architecture ASCII diagram keeps its alignment inside its ```text fence
#   - the Configuration table renders as a table
#   - both badges render side by side and the MIT one links to LICENSE
#   - GitHub shows an "MIT" licence chip in the sidebar (proves Task 1's text is canonical)
#   - the relative links checked locally in Task 8 resolve on the rendered page too
```

`--source . --remote origin --push` does AC6 and AC7 in one step; the alternative
(`gh repo create` bare, then `git remote add origin …`, then `git push -u origin main`) is equivalent
and may be preferred if the maintainer wants to inspect the empty repository first.

**What to do if AC10 finds a rendering defect:** fix it in a follow-up commit and push. Unlike the
publication itself, this is fully reversible — a rendering fix is an ordinary commit.
