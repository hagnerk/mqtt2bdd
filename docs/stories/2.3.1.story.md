# Story 2.3.1: Remove Redundant Reconnection State Machine from dbWriterLoop

## Status

Done

## Story

**As a** developer maintaining the codebase,
**I want** `dbWriterLoop` to not carry a reconnection state machine (`inReconnect` / `attempt`) and its associated log lines,
**so that** the retry logic stays minimal and does not duplicate error reporting already provided by `InsertMessage`.

## Context

Story 2.3 implemented two independent things:

1. **`dbWriterLoop` extraction** — named function replacing the anonymous goroutine. Clean refactor. **Kept.**
2. **Reconnection state machine** — `inReconnect` / `attempt` variables and three log lines (`"Database connection lost"`, `"Attempting database reconnection"`, `"Database reconnected successfully"`). **Superseded by this story.**

The state machine was added to surface reconnection progress in logs. However, `InsertMessage` in `internal/database/queries.go` already logs `ERROR "failed to insert message"` on *every* failure (it fires on each retry, not just the first). The three state-transition log lines therefore provide no diagnostic signal that is not already present. Removing them eliminates ~10 lines of stateful complexity with zero loss of observability.

## Dev Notes

### Rationale

`InsertMessage` (`internal/database/queries.go`, line 30) logs `c.logger.Error("failed to insert message", "sensor", sensor, "error", err)` on **every** call that fails. Since the inner retry loop calls `InsertMessage` on each iteration, the error is already logged repeatedly during an outage. The `inReconnect` flag was introduced solely to suppress duplicate `"Database connection lost"` error lines — a problem created by the new log line itself. Removing the state machine eliminates both the redundancy and the mechanism invented to work around it.

### File to Modify

- `cmd/mqtt2bdd/main.go` — sole file changed
- `internal/database/queries.go` — read only, no changes

### Current State (`cmd/mqtt2bdd/main.go`)

```go
// dbWriterLoop is the sole consumer of msgChan. It retries failed inserts until success,
// ensuring no message is lost during a database outage. Exits when msgChan is closed (story 2.4).
func dbWriterLoop(msgChan <-chan mqtt.Message, dbClient *database.Client, l *slog.Logger) {
	inReconnect := false
	for msg := range msgChan {
		attempt := 0
		for {
			err := dbClient.InsertMessage(context.Background(), msg.Topic, msg.Timestamp, json.RawMessage(msg.Payload))
			if err == nil {
				if inReconnect {
					l.Info("Database reconnected successfully")
					inReconnect = false
				}
				break
			}
			if !inReconnect {
				l.Error("Database connection lost", "error", err)
				inReconnect = true
			}
			attempt++
			l.Info("Attempting database reconnection", "attempt", attempt)
			time.Sleep(defaultRetryIntervalOnDatabaseFailure)
		}
	}
}
```

Call site in `main()`:
```go
go dbWriterLoop(msgChan, dbClient, l)
```

### Target State

```go
// dbWriterLoop is the sole consumer of msgChan. It retries failed inserts until success,
// ensuring no message is lost during a database outage. Exits when msgChan is closed (story 2.4).
func dbWriterLoop(msgChan <-chan mqtt.Message, dbClient *database.Client) {
	for msg := range msgChan {
		for {
			err := dbClient.InsertMessage(context.Background(), msg.Topic, msg.Timestamp, json.RawMessage(msg.Payload))
			if err == nil {
				break
			}
			// error already logged by InsertMessage; hold this message and retry after delay
			time.Sleep(defaultRetryIntervalOnDatabaseFailure)
		}
	}
}
```

Call site in `main()`:
