# Story 1.1: Setup Containerized Development Environment

## Status

## Story

**As a** developer learning Go,
**I want** a one-command development environment setup with PostgreSQL, Mosquitto, and Go containers,
**so that** I can start coding immediately without installing any infrastructure locally.

## Acceptance Criteria

1. `dev/docker-compose.yml` defines three services: `postgres`, `mosquitto`, and `go-dev`
2. All containers use `container_name` directive with `mqtt2bdd-dev-` prefix: `mqtt2bdd-dev-postgres`, `mqtt2bdd-dev-mosquitto`, `mqtt2bdd-dev-go-dev` for easy identification among other projects
3. PostgreSQL container uses official `postgres:15-alpine` image with environment variables for database name, user, and password
4. Mosquitto container uses official `eclipse-mosquitto:2` image with basic configuration allowing anonymous connections
5. Go development container based on `golang:1.23-alpine` (latest stable) with Delve debugger and `staticcheck` linter installed
6. Go container exposes port 2345 for Delve remote debugging
7. Go container mounts project root directory as volume (e.g., `.:/app`) for live code editing
8. SQL initialization script `dev/init-db/01-schema.sql` creates `sensor_metrics` table with schema: `sensor VARCHAR(255), date TIMESTAMP, metrics JSONB`
9. PostgreSQL container automatically executes initialization scripts on first startup
10. All containers start successfully with `docker-compose up` from `dev/` directory
11. Developer can verify PostgreSQL connectivity: `docker exec -it mqtt2bdd-dev-postgres psql -U <user> -d <dbname> -c "\dt"` shows `sensor_metrics` table
12. Developer can verify Mosquitto connectivity: `docker exec -it mqtt2bdd-dev-mosquitto mosquitto_sub -t '#' -v` listens to all topics
13. `.gitignore` includes `.env` file and Docker-related temporary files
14. `dev/.env.example` provides template for required environment variables with documentation
15. `.vscode/launch.json` configuration provided for remote debugging (connects to `localhost:2345`)
16. Manual debugging test: Set breakpoint in VS Code (or compatible IDE), attach debugger to port 2345, run application in container, verify breakpoint is hit and variables can be inspected

### Database Schema (sensor_metrics)

Full DDL for `dev/init-db/01-schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS sensor_metrics (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    sensor VARCHAR(255) NOT NULL,
    date TIMESTAMP NOT NULL,
    metrics JSONB NOT NULL,
    CONSTRAINT unique_sensor_date UNIQUE (sensor, date)
);

CREATE INDEX IF NOT EXISTS idx_sensor_metrics_sensor_date
ON sensor_metrics (sensor, date DESC);

CREATE INDEX IF NOT EXISTS idx_sensor_metrics_metrics
ON sensor_metrics USING GIN (metrics);
```

**Note:** The application does NOT create the schema — it assumes the table exists. The `BIGINT GENERATED ALWAYS AS IDENTITY` pattern is the SQL:2003 standard (preferred over `SERIAL`). The `ON CONFLICT (sensor, date) DO NOTHING` pattern in INSERT operations requires the `unique_sensor_date` constraint defined here.

[Source: architecture/database-schema.md#schema-initialization]

### dev/Dockerfile.dev

Custom image pour le container go-dev. Les outils sont installés à l'image build, pas au démarrage du container :

```dockerfile
FROM golang:1.23-alpine

# git is required by Delve's build process
RUN apk add --no-cache git

# Bake development tools into the image (installed once at build, not on every container start)
RUN go install github.com/go-delve/delve/cmd/dlv@latest && \
    go install honnef.co/go/tools/cmd/staticcheck@latest

WORKDIR /app
```

Build de l'image : `docker-compose build go-dev` (ou automatique au premier `docker-compose up`).

### VS Code Delve Remote Debug Configuration

`.vscode/launch.json` connects to the Go dev container's exposed port 2345:
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Attach to Go in Docker",
      "type": "go",
      "request": "attach",
      "mode": "remote",
      "host": "localhost",
      "port": 2345
    }
  ]
}
```

**Delve workflow — automatique au démarrage :**

Le service `go-dev` dans `docker-compose.yml` lance Delve directement comme commande par défaut :
```
dlv debug --headless --listen=:2345 --api-version=2 --accept-multiclient --continue ./cmd/mqtt2bdd
```
- `--headless` : serveur sans UI, attend les connexions IDE
- `--accept-multiclient` : permet plusieurs attach/detach successifs
- `--continue` : l'application démarre immédiatement sans attendre de debugger attaché

**Workflow normal :**
1. `docker-compose up` → go-dev compile `cmd/mqtt2bdd` et lance Delve automatiquement
2. VS Code : F5 → `"Attach to Go in Docker"` → breakpoint hit
3. Après modification de code : `docker-compose restart go-dev` pour recompiler

**Prérequis :** `go.mod` et `cmd/mqtt2bdd/main.go` doivent exister **avant** `docker-compose up`. Créer ces fichiers en Task 9 avant de démarrer les containers en Task 10.
