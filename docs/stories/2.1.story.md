# Story 2.1: Implement Message Buffering with Channels

## Status

Done

## Story

**As a** system operator,
**I want** incoming MQTT messages buffered in memory,
**so that** temporary database outages don't result in message loss.

## Acceptance Criteria

1. `main.go` creates buffered channel using `cfg.BufferSize` (default 1000): `msgChan := make(chan mqtt.Message, cfg.BufferSize)`
2. `Message` struct defined in `internal/mqtt/types.go` with fields: `Topic string`, `Timestamp time.Time`, `Payload []byte`
3. MQTT message handler (from Story 1.9) sends messages to channel instead of directly inserting to database
4. Separate database writer goroutine consumes messages from channel and calls `database.InsertMessage()`
5. If channel is full (`cfg.BufferSize` messages), MQTT handler logs WARNING and blocks until space is available
6. Database writer goroutine processes messages sequentially from channel
7. Successful writes logged at DEBUG level, failures at ERROR level (satisfied by `InsertMessage`'s internal logging — no duplicate in the goroutine)
8. Manual test: Stop PostgreSQL container, publish 50 MQTT messages, restart PostgreSQL, verify all 50 messages eventually written
9. Channel and goroutine architecture clearly documented in code comments demonstrating Go CSP pattern
10. All code passes `go fmt`, `go vet`, and `staticcheck`

### Previous Story Insights (Story 1.9)

Story 1.9 implemented the goroutine-per-message pattern in `cmd/mqtt2bdd/main.go`. This entire approach is replaced in story 2.1 by the buffered channel + single DB writer goroutine (FIND-009 from QA).

}

### Message Struct

Define in `internal/mqtt/types.go` (same file as `MessageHandler`):

```go
// Message holds a single MQTT message received from the broker.
// It is produced by the MQTT message handler and consumed by the DB writer goroutine.
type Message struct {
    Topic     string
    Timestamp time.Time
    Payload   []byte // Raw JSON as received from the broker
}
```

`Payload` is `[]byte` (not `json.RawMessage`) in the struct. The DB writer converts when calling `InsertMessage`: `json.RawMessage(msg.Payload)`. This conversion is zero-copy — `json.RawMessage` is `type RawMessage []byte`.

[Source: docs/architecture/components.md#component-message-buffer-channel]

### Target `main.go` Structure After Story 2.1

```
1. config.LoadConfig()                  → fatal if error
2. logger.InitLogger()                  → l := ...
3. l.Info("MQTT2BDD starting")          → version logged
4. mqtt.NewClient + Connect             → fatal if error; defer Disconnect
5. database.NewClient + Connect         → fatal if error; defer Close
6. msgChan := make(chan mqtt.Message, cfg.BufferSize)   // CSP producer-consumer channel
7. go func() { for msg := range msgChan { ... } }()   // DB writer goroutine
8. mqttClient.Subscribe("#", channelHandler)           → fatal if error
9. select {}                            → block until killed (signal handling in 2.4)
```

The MQTT handler (step 8) is now:
```go
mqttMessageHandler := func(topic string, payload []byte) {
    msg := mqtt.Message{Topic: topic, Timestamp: time.Now(), Payload: payload}
    select {
    case msgChan <- msg:
    default:
        l.Warn("message buffer full, blocking until space available",
            "buffer_size", cfg.BufferSize)
        msgChan <- msg
    }
}
```

The DB writer goroutine (step 7):
```go
go func() {
    // DB writer goroutine: sole consumer of msgChan, exits when channel closed (story 2.4)
    for msg := range msgChan {
        if err := dbClient.InsertMessage(
            context.Background(), msg.Topic, msg.Timestamp, json.RawMessage(msg.Payload),
        ); err != nil {
            return // error already logged by InsertMessage
        }
    }
}()
```

> **Note on `return` vs `continue`:** `return` inside the `for range` loop will exit the goroutine entirely on the first error. Use `continue` to keep processing subsequent messages even after a failed insert. This is the correct behaviour for resilience — story 2.3 will add retry logic. Use `continue` here.

### BufferSize Configuration

`Config.BufferSize` already exists in `internal/config/config.go` with default 1000. The PRD AC1 says `make(chan Message, 1000)` but coding standards prohibit magic numbers. Use `cfg.BufferSize` — it resolves to 1000 by default and remains configurable via the `BUFFER_SIZE` env var.
