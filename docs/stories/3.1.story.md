1. `Dockerfile` (root directory) implements multi-stage build with two stages: `builder` and `runtime`
2. Builder stage uses `golang:1.23-alpine` image with full Go toolchain
3. Builder stage defines `ARG VERSION=dev` for version injection at build time
4. Builder stage copies source code, runs `go mod download`, and compiles binary: `go build -ldflags="-s -w -X main.Version=${VERSION}" -o /app/mqtt2bdd ./cmd/mqtt2bdd`
5. `cmd/mqtt2bdd/main.go` declares version variable: `var Version = "dev"` (default for local development, overridden by ldflags at build)
6. Builder stage produces statically-linked binary (no dynamic dependencies)
7. Runtime stage uses `alpine:3.23` base image (minimal, no Go toolchain)
8. Runtime stage installs only CA certificates (`ca-certificates` package) for TLS support
9. Runtime stage copies compiled binary from builder stage
10. Runtime stage sets non-root user for security: `USER nobody`
11. Final image size optimized (target <20MB)
12. Dockerfile includes labels: version, description, maintainer
13. `ENTRYPOINT ["/app/mqtt2bdd"]` configured for container execution
14. Manual test: Build image with version: `docker build --build-arg VERSION=0.1.0 -t mqtt2bdd:0.1.0 .`, verify application logs show correct version on startup
15. All code passes `go fmt`, `go vet`, and `staticcheck`
16. **(SM-added, PO-confirmed and widened)** `.dockerignore` (root directory) keeps the build context free of Git metadata, the `dev/` and `docs/` trees, host build artefacts and, above all, **every environment file — `dev/.env` today and a root-level `.env` / `.env.prod` tomorrow** — so no credential can reach any layer of the image or its builder (SEC-001)
17. **(SM-added, PO-confirmed)** `docs/architecture/security.md#container-security` and the two container-base rows of `docs/architecture/tech-stack.md#technology-stack-table` record what this story actually ships (`USER nobody` at UID 65534, `alpine:3.23`, binary at `/app/mqtt2bdd`), so the architecture and the Dockerfile stop contradicting each other. **Facts only** — the *rationale* prose explaining why a static binary and a non-root user matter belongs to Story 3.6 AC9 and is not written here

[Source: docs/architecture/logging-standards.md#domain-fields, docs/architecture/logging-standards.md#event-vocabulary]

### Deviation: AC7 — `alpine:3.23` versus the architecture's `~3.21`

AC7 pins `alpine:3.23`. Two architecture documents pin 3.21:

- `docs/architecture/tech-stack.md#technology-stack-table` — Container Base (Runtime): Alpine Linux `~3.21`; Container Base (Builder): `golang:alpine ~1.23-alpine3.21`
- `docs/architecture/security.md#container-security` — the runtime snippet reads `FROM alpine:3.21`

**Resolution: keep AC7 verbatim; the architecture follows (AC17 / Task 4).** Three reasons:

1. `alpine:3.23` exists and is current — verified against Docker Hub on 2026-07-25, last pushed 2026-06-22.
2. The PRD is the later and more specific artefact here, and a newer Alpine minor is a strictly better security posture on an image whose whole justification is minimal attack surface.
3. Nothing in the application depends on an Alpine version. The binary is static (AC6): the base contributes CA certificates and nothing else.

Note the builder and the runtime now sit on **different Alpine minors** — `golang:1.23-alpine`
currently resolves to Alpine 3.22.1 (measured in the dev image, which is built `FROM golang:1.23-alpine`),
while the runtime is 3.23. That is harmless precisely because `CGO_ENABLED=0` means the binary links
against no libc at all, so nothing built on 3.22 has to match anything on 3.23. This is worth stating
because a reviewer who spots the mismatch will otherwise reasonably ask.

### The Dockerfile

Reference shape. Every line is mapped to the AC it satisfies; write it in this order.

```dockerfile
# syntax=docker/dockerfile:1

# ---- Builder stage: full Go toolchain, discarded after the build ---- (AC1, AC2)
FROM golang:1.23-alpine AS builder

# Injected at build time: docker build --build-arg VERSION=0.1.0 . (AC3)
ARG VERSION=dev

WORKDIR /src

# Dependencies first: this layer is cached until go.mod or go.sum changes. (AC4)
COPY go.mod go.sum ./
RUN go mod download

# Then the source, so editing code does not re-download the module cache. (AC4)
COPY cmd/ ./cmd/
COPY internal/ ./internal/

# CGO_ENABLED=0 is what makes the binary static: no libc, no dynamic loader. (AC6)
# -s -w strip the symbol table and DWARF data: 13.7 MB -> 9.4 MB, which is what
# keeps the final image under the 20 MB target. (AC11)
# -X writes the build version into main.Version. (AC4)
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags="-s -w -X main.Version=${VERSION}" \
    -o /app/mqtt2bdd ./cmd/mqtt2bdd

# ---- Runtime stage: the binary and a CA bundle, nothing else ---- (AC7)
FROM alpine:3.23

# ARG does not cross a FROM boundary; without this line the version label below
# expands to an empty string. (AC3, AC12)
ARG VERSION=dev

# TLS trust store, for a future TLS-enabled broker or database. --no-cache keeps
# the apk index out of the layer. (AC8)
RUN apk add --no-cache ca-certificates

# (AC9) Arrives root-owned and 0755, which is exactly what USER nobody needs.
COPY --from=builder /app/mqtt2bdd /app/mqtt2bdd

# (AC12)
LABEL org.opencontainers.image.version="${VERSION}" \
      org.opencontainers.image.description="MQTT to PostgreSQL bridge for home-automation telemetry" \
      org.opencontainers.image.authors="Kevin Hagner <kevin.hagner@spyzone.fr>"

# (AC10) After apk and COPY, both of which need root. nobody is UID/GID 65534 on Alpine.
USER nobody

# (AC13) Exec form, so the binary is PID 1 and receives SIGTERM directly — which is
# what the graceful shutdown in main.go depends on. Shell form would interpose /bin/sh.
ENTRYPOINT ["/app/mqtt2bdd"]
```

Notes on choices inside that shape:

- **Splitting `COPY` in two** (`go.mod`/`go.sum`, then `cmd/` and `internal/`) still satisfies AC4 — it copies source code, runs `go mod download`, and compiles — while giving the module download its own cache layer. It also means `dev/`, `docs/` and `.git` never enter a layer even if `.dockerignore` were deleted. Copy only `cmd/` and `internal/` — those are the only two Go source trees in the repository. (The SM's draft said "`pkg/` is empty"; in fact `pkg/` does not exist at all, and neither does `test/` yet. The instruction is unchanged, but do not go looking for either.)
- **`# syntax=docker/dockerfile:1`** is optional. Include it or not; it changes nothing this story is judged on.
- **`WORKDIR /src`** in the builder is a working directory for the compile, not the runtime layout. The runtime stage deliberately has no `WORKDIR` — `ENTRYPOINT` is an absolute path.
- **Label keys** use the OCI image-spec annotation names. AC12 asks for "version, description, maintainer"; `org.opencontainers.image.authors` is the standard key for maintainer, and the deprecated `MAINTAINER` **instruction** must not be used. The maintainer value comes from the repository's Git identity. [Source: git config user.name / user.email]

### Static Linking (AC6)

**Build environment:** `CGO_ENABLED=0 GOOS=linux`, set inline on the `go build` command in the builder
stage. `CGO_ENABLED=0` is the whole mechanism — it forces the pure-Go implementations of `net` and
`os/user`, so nothing links against musl and the result needs no dynamic loader. `GOOS=linux` is
explicit rather than inherited, so the Dockerfile documents its own target.

**Do not set `GOARCH`.** Unset, the build targets the daemon's own architecture. That is correct for
this project: images are built locally on the deployment host
[Source: docs/architecture/tech-stack.md#deployment-architecture]. Note the maintainer's machine is
arm64, so every figure in this story was measured on arm64; an amd64 build produces a slightly larger
binary but the same relationship to the 20 MB target.

**Neither dependency needs cgo.** `paho.mqtt.golang` is pure Go, and `pgx/v5` is a pure-Go PostgreSQL
driver — that is one of the reasons it was chosen over alternatives.
[Source: docs/architecture/tech-stack.md#technology-stack-table]

**Verification, two independent checks (Task 5):**

1. Inside the image: `docker run --rm --entrypoint sh mqtt2bdd:0.1.0 -c 'ldd /app/mqtt2bdd; echo "ldd exit=$?"'`. musl's `ldd` prints `Not a valid dynamic program` and exits non-zero for a static binary. **The non-zero exit is the pass.** A list of `.so` dependencies is the failure.
2. From the recorded build settings, inside `go-dev`: `go version -m <binary>` prints `build CGO_ENABLED=0`, `build GOOS=linux` and the `-ldflags` string. Go embeds these in every binary since 1.18. Measured today in the dev container against exactly this command line: `CGO_ENABLED=0`, `GOARCH=arm64`, `GOOS=linux`, `-ldflags="-s -w -X main.Version=0.1.0"`.

Both checks are needed. Check 1 alone is weak — a cgo binary built on `golang:1.23-alpine` links
against musl and would still *run* on `alpine:3.23`, so "it started" proves nothing about linkage.

### Image Size Budget (AC11)

**Every figure below was measured by the PO on 2026-07-25, arm64, against the real images** — the images
were pulled and built, and `docker image inspect --format '{{.Size}}'` was read. Nothing here is an
estimate or a Docker Hub lookup. The SM's original table over-stated the `ca-certificates` cost by roughly
2.5× and reported the base in MiB while labelling it MB; both are corrected.

| Component | Size (bytes) | How measured |
| --------- | -----------: | ------------ |
| `alpine:3.23` base | 8,657,696 | `docker image inspect alpine:3.23` |
| `apk add --no-cache ca-certificates`, **incremental** | 525,348 | built a two-line probe image and subtracted the base |
| Binary, `-s -w`, `CGO_ENABLED=0` | 9,371,800 | built in `go-dev` with AC4's exact command line |
| Binary, **unstripped**, for comparison | 13,665,922 | `bin/mqtt2bdd` in the working tree |
| **Projected total** | **18,554,844** | ≈18.55 MB decimal / 17.70 MiB |

**AC11 passes under both readings of "20MB":** decimal (20,000,000 — margin 1,445,156 bytes, 7.2%) and
binary (20,971,520 — margin 2,416,676 bytes, 11.5%). The story is not as tight as the draft feared, but
it is tight enough that nothing may be added casually.

Three consequences:

- **`-s -w` is mandatory.** They are worth 4,294,122 bytes (13,665,922 → 9,371,800). Without them the total lands near 22.8 MB and AC11 fails outright.
- **`--no-cache` on `apk add` is mandatory.** The apk index is several MB and is pure waste in a layer.
- **Add nothing.** No `tzdata`, no `curl`, no `busybox-extras`, not "while we're here".

**Worth knowing before you touch AC8:** `alpine:3.23` **already ships `ca-certificates-bundle`**, and
`/etc/ssl/certs/ca-certificates.crt` (182,789 bytes) already exists in the bare base — verified by running
`apk info` and `ls` inside it. So AC8's `apk add ca-certificates` is buying the OpenSSL-backed
`update-ca-certificates` *tooling*, not the trust store itself. A static Go binary only ever *reads* that
file. Install it anyway: AC8 is PRD-owned and names the package. But this is why the fallback below is
safe rather than a compromise.

#### PO fallback ladder if the built image exceeds 20,000,000 bytes

Decided in advance on 2026-07-25 so the Dev agent is never blocked waiting on an arbitration. Work the
