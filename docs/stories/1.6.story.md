### Subscribe Method — Authoritative Specification

**Method signature:**
```go
func (c *Client) Subscribe(topic string, handler MessageHandler) error
```

**Receiver:** `c` (consistent with `Connect`, `Disconnect`, `IsConnected`)

**QoS constant (file-level, unexported):**
```go
const qos0 = byte(0)
```

Place this constant in the `const` block at the top of `client.go` (before type declarations, per file organization standard).

**Paho callback adapter pattern:**

Our `MessageHandler` type is `func(topic string, payload []byte)`, but Paho's callback type is `func(mqtt.Client, mqtt.Message)`. Adapt inside Subscribe:

```go
token := c.pahoClient.Subscribe(topic, qos0, func(_ mqtt.Client, msg mqtt.Message) {
    handler(msg.Topic(), msg.Payload())
})
```

The `_` discards the Paho client argument — we have no need for it in our callback.

**Token wait pattern (Paho v1.5.0):**
```go
select {
case <-token.Done():
}
if err := token.Error(); err != nil {
    c.logger.Error("MQTT subscription failed", "topic", topic, "error", err)
    return fmt.Errorf("failed to subscribe to topic %s: %w", topic, err)
}
```

No context parameter for `Subscribe` — blocking wait with no timeout is acceptable here (broker acknowledgment is near-instantaneous on a healthy connection). Connection timeout concern (FIND-004) applies to `Connect`, not `Subscribe`.

**AC9 — goroutine behavior:**

Paho invokes the message callback in its own internally managed goroutine for each received message. There is no explicit `go` statement needed in our code. AC9 is satisfied by the Paho library's behavior — document this in the godoc.

**Full implementation:**
```go
// Subscribe registers handler to be called for each message received on topic.
// It uses QoS 0 (at-most-once delivery). The wildcard topic "#" captures all
// published topics. The handler is invoked in a goroutine managed by the Paho
// library — Subscribe returns immediately after the broker acknowledges the
// subscription.
func (c *Client) Subscribe(topic string, handler MessageHandler) error {
    c.logger.Info("subscribing to MQTT topic", "topic", topic)
    token := c.pahoClient.Subscribe(topic, qos0, func(_ mqtt.Client, msg mqtt.Message) {
        handler(msg.Topic(), msg.Payload())
    })
    select {
    case <-token.Done():
    }
    if err := token.Error(); err != nil {
        c.logger.Error("MQTT subscription failed", "topic", topic, "error", err)
        return fmt.Errorf("failed to subscribe to topic %s: %w", topic, err)
    }
    c.logger.Info("MQTT subscribed", "topic", topic)
    return nil
}
```

### Updated `main.go` — Startup Sequence After This Story

```go
package main

import (
    "context"
    "log"
    "os"

    "github.com/spydemon/mqtt2bdd/internal/config"
    "github.com/spydemon/mqtt2bdd/internal/logger"
    "github.com/spydemon/mqtt2bdd/internal/mqtt"
)

var Version = "dev"

func main() {
    cfg, err := config.LoadConfig()
    if err != nil {
        log.Fatalf("configuration error: %v", err)
    }

    l := logger.InitLogger(cfg.LogLevel)
    l.Info("MQTT2BDD starting", "version", Version)

    mqttClient := mqtt.NewClient(cfg, l)
    if err := mqttClient.Connect(context.Background()); err != nil {
        os.Exit(1)
    }
    defer mqttClient.Disconnect()

    handler := func(topic string, payload []byte) {
        preview := payload
        if len(preview) > 100 {
            preview = preview[:100]
        }
        l.Debug("message received", "topic", topic, "payload_length", len(payload), "payload_preview", string(preview))
    }
    if err := mqttClient.Subscribe("#", handler); err != nil {
        l.Error("MQTT subscribe failed", "error", err)
        os.Exit(1)
    }

    select {} // Block until process is killed — signal handling added in story 2.x
}
```

**Note on `select {}`:** This is an intentional temporary block to keep the application alive while Paho receives messages in the background. Signal handling (SIGTERM/SIGINT) for graceful shutdown is out of scope for this story and will be implemented later.

**Note on Subscribe error logging:** Unlike `Connect`, `Subscribe` is NOT called already-logged inside `main.go` — the `l.Error(...)` in the Subscribe error branch of `main.go` IS correct here (Subscribe error in `main.go` adds context that Subscribe itself doesn't have). This is different from the FIND-001 fix in story 1.5 where `Connect` already logs inside itself.
