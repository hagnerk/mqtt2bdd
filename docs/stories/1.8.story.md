### InsertMessage — Full Implementation

`InsertMessage` is a method on `*Client` defined in a separate file `queries.go` to separate connection lifecycle (client.go) from query operations (queries.go):

```go
const maxSensorLen = 255

// InsertMessage inserts a sensor metric row into sensor_metrics.
// If sensor exceeds 255 characters, it is truncated to the last 255 characters
// and a WARN is logged. Uses ON CONFLICT (sensor, date) DO NOTHING for idempotent
// writes. Logs DEBUG on success, WARN on duplicate, ERROR on failure.
func (c *Client) InsertMessage(ctx context.Context, sensor string, timestamp time.Time, metrics json.RawMessage) error {
    sensorRunes := []rune(sensor)
    if len(sensorRunes) > maxSensorLen {
        c.logger.Warn("sensor name truncated",
            "original_length", len(sensorRunes),
            "truncated_sensor", string(sensorRunes[len(sensorRunes)-maxSensorLen:]),
        )
        sensor = string(sensorRunes[len(sensorRunes)-maxSensorLen:])
    }

    const query = `
        INSERT INTO sensor_metrics (sensor, date, metrics)
        VALUES ($1, $2, $3)
        ON CONFLICT (sensor, date) DO NOTHING
    `

    commandTag, err := c.pool.Exec(ctx, query, sensor, timestamp, metrics)
    if err != nil {
        c.logger.Error("failed to insert message",
            "sensor", sensor,
            "error", err,
        )
        return fmt.Errorf("failed to insert message for sensor %s: %w", sensor, err)
    }

    if commandTag.RowsAffected() == 0 {
        c.logger.Warn("duplicate message ignored",
            "sensor", sensor,
            "timestamp", timestamp.Format(time.RFC3339),
        )
    } else {
        c.logger.Debug("message persisted",
            "sensor", sensor,
            "timestamp", timestamp.Format(time.RFC3339),
            "payload_size", len(metrics),
        )
    }

    return nil
}
```

> **Note on truncation:** The truncation operates on runes (Unicode code points), not bytes, ensuring correct behavior regardless of the character encoding of the topic. `maxSensorLen` maps to the 255-character limit of the `sensor VARCHAR(255)` column.

### SQL — ON CONFLICT Behavior

The `UNIQUE(sensor, date)` constraint on `sensor_metrics` makes duplicate (sensor + timestamp) inserts fail at the DB level. `ON CONFLICT (sensor, date) DO NOTHING` turns that constraint violation into a silent skip, returning `RowsAffected() == 0` instead of an error:

- `RowsAffected() == 1` → row inserted → log DEBUG
- `RowsAffected() == 0` → duplicate → log WARN, return nil (not an error)

### Security

`c.pool.Exec(ctx, query, sensor, timestamp, metrics)` uses pgx parameterized queries — `$1`, `$2`, `$3` are bound separately from the query string, making SQL injection impossible at the driver level.

The `metrics json.RawMessage` field contains raw MQTT payload — it is stored as-is in JSONB without server-side validation. This is intentional (schema-on-read design).

### Refactoring Performed

- **File**: `internal/database/integration_test.go`
  - **Change**: Removed `defer pool.Close()` from `TestMain`; removed `os.Exit(1)` on the post-test truncate; replaced with a best-effort `pool.Exec(...)` and no explicit Close.
  - **Why**: `defer` does not run before `os.Exit()` in Go — making it dead and misleading code. The `os.Exit(1)` on post-test cleanup was overriding the real test result (`code`) if the truncate happened to fail. Explicitly closing the pool before `os.Exit` in a test binary is cargo-cult: the OS closes all sockets on process exit, and PostgreSQL handles abrupt disconnections gracefully with no side effects.
